# Breaking changes — v10.0.0

## Summary

Two things land together in v10:

1. **The lexicon manifest is refreshed to the CIDs currently published on the
   AT Proto network.** Five lexicons had been republished since v9.17.1 was cut.
   One of those republications **removes public API**: upstream dropped the
   `accountStats` / `recordsStats` defs from `tools.ozone.moderation.defs`, so
   the generated `AccountStats` and `RecordsStats` classes, and the two
   `SubjectStatusView` properties that referenced them, are gone. The other four
   only add optional fields, which is still binary-breaking for the data classes
   that gained them.
2. **The thread V2 read is adopted**: `app.bsky.unspecced.getPostThreadV2`,
   `getPostThreadOtherV2` and `app.bsky.unspecced.defs`, with a new
   `UnspeccedService`. This part is purely additive.

If you do not use `tools.ozone.*` and you construct generated models with named
arguments, **v10 is a version bump with no code change**.

## What changed

### Removed — `tools.ozone.moderation`

| Removed | Was |
|---|---|
| `tools.ozone.moderation.AccountStats` | `appealCount`, `escalateCount`, `reportCount`, `suspendCount`, `takedownCount` |
| `tools.ozone.moderation.RecordsStats` | `appealedCount`, `escalatedCount`, `pendingCount`, `processedCount`, `reportedCount`, `subjectCount`, `takendownCount`, `totalReports` |
| `SubjectStatusView.accountStats` | `AccountStats?` |
| `SubjectStatusView.recordsStats` | `RecordsStats?` |

Upstream removed these defs from the lexicon and the server no longer sends
them. They are not kept alive through an overlay: unlike the `chat.bsky.group`
overlays, no lexicon in this SDK's manifest still refers to them, so a vendored
copy would describe fields that can never be populated.

### New optional fields on existing models (binary-breaking, source-compatible)

Every data class below gains at least one constructor parameter. The generator
orders constructor parameters alphabetically, so the JVM signatures of the
constructor, `copy`, `copy$default` and the `componentN` functions shift.

| Model | New fields |
|---|---|
| `app.bsky.embed.ExternalView` | `data: ExternalViewDataUnion?` |
| `app.bsky.embed.ExternalViewArticle` | `providerId: String?`, `viewer: ExternalViewArticleViewerState?` |
| `app.bsky.embed.ExternalViewArticlePublication` | `providerId: String?`, `viewer: ExternalViewArticlePublicationViewerState?` |
| `app.bsky.embed.ExternalViewGallery` | `photoCount: Long?`, `providerId: String?`, `viewer: ExternalViewGalleryViewerState?` |
| `app.bsky.embed.ExternalViewLivestream` | `providerId: String?` |
| `app.bsky.feed.PostView` | `viewCount: Long?` |
| `app.bsky.feed.Interaction` | `payload: AtField<JsonObject>`, `viewContext: AtField<String>` |
| `tools.ozone.queue.QueueStats` | `acknowledgedCount`, `ahtDurationSec`, `ahtSampleCount`, `avgResolutionTimeSec`, `closedCount`, `labelActionCount`, `resolutionDurationSec`, `resolutionSampleCount`, `tagActionCount`, `takedownActionCount` |
| `tools.ozone.queue.QueueView` | `accountTags`, `reporterTags`, `strictAccess` |

New types that come with them: `ExternalViewDataUnion` (an open union with the
usual `Unknown` member; `ExternalViewArticle`, `ExternalViewArticlePublication`,
`ExternalViewGallery` and `ExternalViewLivestream` now implement it),
`ExternalViewArticleViewerState`, `ExternalViewArticlePublicationViewerState`
and `ExternalViewGalleryViewerState`.

`app.bsky.feed.getAuthorFeed` gains a known `filter` value,
`posts_and_replies_only`. `filter` is a `String`, so there is no API change.

#### The one source-level trap: `ExternalView`

`ExternalView` used to have a single constructor parameter, so a positional
call compiled. `data` now sorts ahead of `external`:

```kotlin
// before (v9) — compiled
ExternalView(someExternal)

// after (v10) — does not compile: the first parameter is now `data`
ExternalView(external = someExternal)
```

Destructuring is affected the same way: `val (external) = view` now binds
`data`. Use the property.

### Added — `app.bsky.unspecced` thread V2

New package `io.github.kikin81.atproto.app.bsky.unspecced`:

- `UnspeccedService(client).getPostThreadV2(GetPostThreadV2Request)` and
  `.getPostThreadOtherV2(GetPostThreadOtherV2Request)`.
- `GetPostThreadV2Response(thread, hasOtherReplies, threadgate)`, where `thread`
  is a flat, server-ordered `List<GetPostThreadV2ThreadItem>` of
  `{ uri, depth, value }`.
- `ThreadItemPost` (with `moreParents`, `moreReplies`, `opThread`,
  `opThreadPostIndex`, `opThreadPostCount`, `hiddenByThreadgate`,
  `mutedByViewer`), `ThreadItemBlocked`, `ThreadItemNotFound`,
  `ThreadItemNoUnauthenticated`.
- The other defs in `app.bsky.unspecced.defs` (`TrendView`, `SkeletonSearchPost`,
  `AgeAssuranceState`, …) are generated too, because the defs file is vendored
  whole. No queries for them are opted in.

```kotlin
val thread =
    UnspeccedService(client).getPostThreadV2(
        GetPostThreadV2Request(anchor = AtUri(postUri), below = 10, branchingFactor = 1, sort = "top"),
    )
```

These lexicons are vendored as overlays: `app.bsky.unspecced.*` has no
on-network lexicon authority, so `lex install` cannot fetch them. Upstream marks
both endpoints experimental ("WILL change without notice").

**Read this before using them.** An open-union member the SDK cannot decode
does not fail the response: it comes back as the union's `Unknown` member. That
holds for a brand-new item kind and equally for a `threadItemPost` whose shape
has changed. A consumer that skips `Unknown` items must not also treat "no
readable anchor item" as "post not found": check the depth-0 item explicitly and
fall back to `app.bsky.feed.getPostThread` when it is `Unknown`.

### Unchanged

- `:runtime`, `:oauth`, `:compose` and `:compose-material3` are untouched.
- No generated `*Service` method signature changes.
- No `app.bsky.*` or `chat.bsky.*` type is removed or renamed.
- Wire behavior for every existing call is identical.

## How to migrate

### 1. Bump the dependency

```kotlin
// before
implementation("io.github.kikin81.atproto:models:9.x.x")

// after
implementation("io.github.kikin81.atproto:models:10.0.0")
```

Bump every `io.github.kikin81.atproto` artifact together; they are released at
one version.

### 2. If you read Ozone subject stats

Delete the reads of `SubjectStatusView.accountStats` / `.recordsStats` and any
use of `AccountStats` / `RecordsStats`. There is no replacement field on
`SubjectStatusView`; the server stopped sending them.

### 3. If you construct or destructure generated models positionally

Switch to named arguments for the models in the table above. `ExternalView` is
the one that fails to compile; the others gain parameters that have defaults,
but positional calls to them now put values in the wrong slot whenever a new
parameter sorts ahead of an existing one.

### 4. Everyone else

Recompile. Nothing to change.

## Why this is a major bump

Per the kotlinx-binary-compatibility-validator (gating this repo at
`:models:apiCheck`):

- Two public classes and two public properties are removed. That is a
  source-level break for any consumer that referenced them.
- Nine data classes gain constructor parameters, which changes the JVM
  descriptors of their constructors, `copy` functions and `componentN`
  accessors. Per repo discipline (see `v5.md` through `v9.md`), that is
  binary-breaking even where it is source-compatible.

The pin refresh could not be deferred: `npx lex install --ci` fails on every
branch, `main` included, once the network has republished a pinned lexicon, so
no pull request could pass CI until the manifest caught up.

The `app.bsky.unspecced` addition alone would have been a minor release. It
ships in the same release because it was the change in flight when the pins
went stale.

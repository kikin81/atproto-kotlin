# Breaking changes — v6.0.0

## Summary

Adds AT Protocol service-routing support (the `atproto-proxy` HTTP
header) and exposes the OAuth scope on `AtOAuth`, which together
unblock `chat.bsky.convo.*` calls that previously returned 403
ScopeMissingError. **Kotlin source code does not need changes for
existing callers** — every new parameter is optional and defaults
to the previous behavior. **Recompilation against 6.0.0 is
required** because the JVM signatures of `XrpcClient.query` /
`procedure`, the generated `ConvoService` constructor, and the
`AtOAuth` constructor all changed.

## What changed

### Runtime — `XrpcClient`

A new optional parameter `proxy: String? = null` was appended to all
four public methods. When non-null, the value is sent as the
`atproto-proxy` HTTP header on the outgoing request and is preserved
across the existing 401 / DPoP-nonce retry path.

| Method | Before | After |
|---|---|---|
| `query(...)` | ends with `auth: AuthProvider? = null` | now ends with `auth: AuthProvider? = null, proxy: String? = null` |
| `procedure(...)` (JSON body) | same | same — gained `proxy: String? = null` at the end |
| `procedure(...)` (no input) | same | same — gained `proxy: String? = null` at the end |
| `procedure(...)` (raw bytes) | same | same — gained `proxy: String? = null` at the end |

### Models — generated services for proxied namespaces

`ConvoService` (and any future generated service whose namespace is
listed in the generator's `ProxyMapping` table) gains an optional
constructor parameter that holds the proxy DID:

| Class | Before | After |
|---|---|---|
| `ConvoService` | `class ConvoService(client: XrpcClient)` | `class ConvoService(client: XrpcClient, proxy: String? = "did:web:api.bsky.chat#bsky_chat")` |

Generated services for non-proxied namespaces (`FeedService`,
`ActorService`, etc.) are emitted byte-identical to v5 — their
constructors and method signatures are unchanged.

### OAuth — `AtOAuth`

A new optional parameter `scope: String = "atproto transition:generic"`
was appended to the `AtOAuth` constructor. The value is sent verbatim
as the `scope` form parameter in the PAR request. In v5.x the scope
was hardcoded at the call site, so consumers could not request
umbrella scopes like `transition:chat.bsky` (chat AppView),
`transition:email`, or any future per-service `transition:*` scope
even if they were declared in the hosted `client-metadata.json`.

| Class | Before | After |
|---|---|---|
| `AtOAuth` | `AtOAuth(clientMetadataUrl, sessionStore, httpClient, json)` | `AtOAuth(clientMetadataUrl, sessionStore, httpClient, json, scope = "atproto transition:generic")` |

The requested `scope` must remain a subset of the `scope` advertised
by the hosted client metadata document; the authorization server
rejects requests for scopes not registered in metadata.

### Behavioral change (bug fix)

In v5.x, `ConvoService(client).listConvos()` against an
authenticated production Bluesky session returned:

```
ScopeMissingError: Missing required scope
  "rpc:chat.bsky.convo.listConvos?aud=did:web:api.bsky.app" (HTTP 403)
```

In v6.0.0 the same call succeeds — the request is correctly routed
to `did:web:api.bsky.chat`. Consumers explicitly relying on the 403
(unlikely) should adjust their error-handling expectations.

## How to migrate

### 1. Bump the dependency

**Gradle Kotlin DSL:**

```kotlin
// before
implementation("io.github.kikin81.atproto:runtime:5.x.x")
implementation("io.github.kikin81.atproto:models:5.x.x")

// after
implementation("io.github.kikin81.atproto:runtime:6.0.0")
implementation("io.github.kikin81.atproto:models:6.0.0")
```

### 2. Recompile

If your project has any pre-built artifacts (jars, modules) that link
against the v5 `XrpcClient` or v5 `ConvoService`, rebuild them against
v6. The Kotlin source is unchanged, so the recompilation is a
no-touch step.

### 3. Java callers using explicit overloads

Java does not see Kotlin's default parameter values. If you call
`XrpcClient.query` / `procedure` from Java with the full positional
argument list, add `null` (or your proxy DID) before the
`Continuation` argument:

```java
// before
client.query(nsid, params, ps, rs, errorMapper, auth, continuation);

// after
client.query(nsid, params, ps, rs, errorMapper, auth, /* proxy */ null, continuation);
```

Java callers that go through the Kotlin-generated `*$default`
synthetic accessors require no changes.

### 4. Optional: customize the proxy

If you run your own AT Protocol stack (sandbox, staging, self-hosted
chat appview), you can route chat traffic to a different endpoint by
overriding the proxy at construction:

```kotlin
val convo = ConvoService(client, proxy = "did:web:custom.sandbox.example#bsky_chat")
// or, to bypass proxying entirely for direct PDS testing:
val convo = ConvoService(client, proxy = null)
```

### 5. Optional: request additional OAuth scopes

The default `scope = "atproto transition:generic"` matches v5
behavior. To request umbrella scopes, pass them via the new
constructor argument and make sure the same scopes appear in your
hosted `client-metadata.json`:

```kotlin
val oauth = AtOAuth(
    clientMetadataUrl = "https://app.example.com/oauth/client-metadata.json",
    sessionStore = mySessionStore,
    httpClient = myKtorClient,
    scope = "atproto transition:generic transition:chat.bsky",
)
```

The consent screen will then show the additional scopes, and the
minted access token will authorize the corresponding RPCs (e.g.
`chat.bsky.convo.*` against `did:web:api.bsky.chat`).

## Why this isn't a no-op minor

The new parameters all have defaults, so source-level Kotlin is
unchanged. But the compiled JVM method descriptors for
`XrpcClient.query` / `procedure`, the `ConvoService` constructor,
and the `AtOAuth` constructor all gained a `Ljava/lang/String;`
slot. Pre-built bytecode against v5 will fail with
`NoSuchMethodError` at link time against the v6 artifacts. Per JVM
ABI conventions and the project's existing breaking-changes
discipline (see `v5.md`), this warrants a major bump.
